# public/.htaccess

## ¿Para qué sirve?
Es la configuración de Apache para cuando el servidor apunta **directamente a la carpeta `public/`**
(por ejemplo, en un hosting). Hace cuatro cosas: enviar todo a `index.php`, proteger archivos privados,
**entregar los archivos comprimidos** y **decirle al navegador cuánto tiempo guardarlos**.

## ¿Con qué se conecta?
| Dirección | Archivo |
|---|---|
| → envía a | `public/index.php` |
| Trabaja junto con | el `.htaccess` de la raíz (que manda las peticiones hacia `public/`) |

## Código explicado
```apache
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.php [L]
```
| Línea | Significado |
|---|---|
| `RewriteCond ... !-f` | Si lo pedido **no** es un archivo que existe... |
| `RewriteCond ... !-d` | ...y **no** es una carpeta que existe... |
| `RewriteRule ^ index.php [L]` | ...entonces envíalo a `index.php`. |

Así las imágenes y el JavaScript se entregan directo, y todo lo demás lo responde PHP.

### Entregar la copia comprimida (.gz)
```apache
RewriteCond %{HTTP:Accept-Encoding} gzip
RewriteCond %{REQUEST_FILENAME}.gz -f
RewriteRule ^(.+\.(js|css))$ $1.gz [L]
```
| Línea | Significado |
|---|---|
| `RewriteCond %{HTTP:Accept-Encoding} gzip` | Si el navegador avisa que **acepta archivos comprimidos**... |
| `RewriteCond %{REQUEST_FILENAME}.gz -f` | ...y existe la copia `.gz` (la crea `npm run build`)... |
| `RewriteRule ^(.+\.(js|css))$ $1.gz [L]` | ...entrega `main.js.gz` en vez de `main.js` (pesa unas 3 veces menos). |

```apache
<FilesMatch "\.js\.gz$">
    ForceType application/javascript
</FilesMatch>
```
Le dice al navegador que la copia `.js.gz` **es JavaScript** (y la `.css.gz` es CSS), y con
`Header set Content-Encoding gzip` le avisa que viene comprimida para que la descomprima solo.

Se hace así (y no con `mod_deflate`) porque en Laragon la compresión de Apache viene **apagada**. El bloque
`<IfModule mod_deflate.c>` queda por si el servidor del hosting sí la tiene: ahí también comprime lo demás.

### Cuánto tiempo guardar cada archivo (`Cache-Control`)
| Archivos | Cuánto | Por qué |
|---|---|---|
| `assets/chunks/*-XXXXXXXX.js` | 1 año (`immutable` = nunca cambia) | El código en el nombre cambia si el archivo cambia. |
| `main.css` | 1 año | La cabecera le pone `?v=fecha`: si cambia, la dirección es otra. |
| `main.js` | `no-cache` (se guarda, pero siempre pregunta si cambió) | Va **sin `?v=`** porque los archivos de cada pantalla lo importan con esa dirección exacta (ver `views/layouts/pie.md`). Si no cambió, el servidor responde "304" sin reenviarlo. |
| íconos y letras | 1 semana | Casi nunca cambian. |
| `sw.js` | `no-cache` (siempre se revisa) | Para que los cambios del Service Worker lleguen enseguida. |

```apache
<FilesMatch "\.(env|sql|log)$">
    Require all denied
</FilesMatch>
```
Si por error queda un archivo `.env`, `.sql` o `.log` dentro de `public/`, nadie lo puede descargar
(tienen contraseñas o datos).

## ¿Qué pasa si se borra?
| Si se borra… | Qué pasa |
|---|---|
| el archivo | si el servidor apunta a `public/` (hosting), solo abre `/`; las demás direcciones (`/login`, `/api/...`) dan 404. En Laragon no se nota, porque manda el `.htaccess` de la raíz. |
| las 3 líneas `RewriteCond` / `RewriteRule` | igual que arriba: 404 en todo lo que no sea un archivo real |
| las 3 líneas de la copia `.gz` | todo funciona, pero los archivos viajan sin comprimir (más lento) |
| los `ForceType` o el `Content-Encoding gzip` | **la página sale en blanco**: el navegador recibe el archivo comprimido sin saber que lo está |
| el bloque `<IfModule mod_headers.c>` | todo funciona, pero el navegador vuelve a preguntar por cada archivo en cada visita |
| el bloque `<FilesMatch>` de `.env/.sql/.log` | todo sigue funcionando, pero un `.env`, `.sql` o `.log` dejado en `public/` se podría descargar |
